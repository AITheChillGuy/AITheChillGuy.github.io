MERA — Medical Electronic Records Assistant

A retrieval pipeline that unifies medical QA, report summarization, and patient-case similarity into one domain-specific assistant.

Role
AI Research Specialist · WCM-Q
Stack
Python · LangChain · RAG · Mistral · Qwen · Llama
Data
Synthetic clinical · MIMIC-IV-Note (de-identified)
Year
2025
Venue
Machine Learning and Knowledge Extraction · MDPI
Status
Published

The problem. Three different clinical questions tend to need three different tools — medical question answering, report summarization, and patient-case similarity search. Most assistants split each into its own pipeline, with its own retrieval, prompts, and evaluation. That's a lot of moving parts to maintain.

The approach. A single end-to-end Retrieval-Augmented Generation pipeline, behind one domain-specific retriever, that serves all three tasks. The training set was generated synthetically using Mistral, Qwen, and Llama, and the system was validated on de-identified MIMIC-IV-Note records.

One retriever, three clinical tasks — validated on real EHR notes.

What was hard. Evaluation. The system was scored across five complementary signals — correctness, groundedness, ROUGE-1 F1, Jaccard, and METEOR — so a model that did well on one metric still had to hold up on the others.

What shipped. A peer-reviewed assistant in Machine Learning and Knowledge Extraction (MDPI, 2025), with the unified retrieval pipeline, the synthetic data approach, and the multi-metric evaluation documented end-to-end.

What this changes. A reusable template for clinical RAG: one retriever, one evaluation harness, multiple downstream tasks behind it.

Published in Machine Learning and Knowledge Extraction, MDPI, 2025. Validated on de-identified MIMIC-IV-Note records.
